# Client walkthrough — report case study

Allow about four minutes. Follow one case through **Activity → Evidence → Assessment → Recommendation → Reapplication**.

If an older browser workspace opens, export it, then select **Preview report update**. The preview explains how report cases are added while retaining earlier activities and evidence. Report copies may have codes such as A1-R1.

## 1. Dashboard: explain the method

> “This workspace demonstrates a repeatable human assessment of AI-assisted engineering work. The report consolidates 40 studies into 15 concepts and six provisional groupings. We apply the same criteria to three different activities.”

Use the comparison table to point to A1, A2 and A3. Open A1’s **Quality Risk & Validation Adequacy** cell.

> “Evidence availability and the qualitative rubric condition answer different questions. Neither is a numerical risk score.”

Avoid describing the Present percentage as safety, quality, or test coverage.

## 2. Activity profiles: establish what happened

Open **Activity profiles → A1**.

> “The profile describes the bounded bug fix, AI involvement, human responsibility and remaining limits. Its supporting records identify the evidence sources and stakeholder clarification used by the report.”

Show E05 and the clarification note. Explain that these are report reference summaries. Original screenshots are not bundled. Additional non-confidential files can be attached here, then explicitly linked to criteria in the rubric. The app does not analyze uploads or assign their status.

For A2, explain that Cloudbreak remains a pilot; A1’s E04 readiness output is not applied to it. For A3, explain that review is advisory and human participants retain approval and merge authority.

## 3. Assessment rubric: explain the judgement

Open A1 → **Quality Risk & Validation Adequacy**.

> “The report records Present because evidence establishes the validation condition. That evidence also shows a missing automated regression guard. The separate qualitative condition is Intermediate. Present does not mean adequate or safe.”

Point to the rationale, linked evidence and unresolved condition. Expand the rubric definitions. No status automatically selects a qualitative condition. Show the report reference and explain that the records remain In review until a named human records a new app review checkpoint.

Use a new synthetic activity if demonstrating edits, rather than replacing the report findings during the presentation.

## 4. Recommendation map: connect findings to action

Choose **Validation**.

> “The report proposes checking regression coverage against the changed behaviour. The live follow-up rule remains open because a condition is unresolved. We can inspect its rationale, evidence links and exact rule.”

Distinguish source proposals from current rule-based prompts. The A1 oversight source cell needs editorial clarification because it repeats technical-controls wording; the app flags that issue and retains the separate approval limitation.

## 5. Reapplication: show why this is repeatable

Open **Method & concepts → Update workflow**.

> “Changes in permissions, validation, repository context, AI authority or new research trigger reassessment. The current six groupings can become five, seven or another supported count through a reviewed method update.”

Show the triggers and six-step procedure. Method JSON previews additions, changes and retired definitions; earlier evidence and judgements are retained. Changed criteria or evidence require explicit human reapplication.

End by exporting JSON. Explain that this version saves in the current browser; JSON transfers the workspace between browsers or preview hostnames. Excel → KNIME → reviewed JSON → GitHub remains a manual reviewed process.
